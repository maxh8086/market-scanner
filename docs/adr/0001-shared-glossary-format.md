# ADR 0001: Shared glossary file format, loader and gates

* **Status:** Accepted (2026-10-31). User approved the ADR as written.
* **Design:** [docs/designs/shared-glossary.md](../designs/shared-glossary.md)

## Context

The workbook (`scanner/workbook.py`), the model prompt (`scanner/conclude.py`) and the UI (`ui/`, later Node) each need the same column text: label, tooltip, explanation and derivation. Today that text is duplicated and has already drifted. The wireframe keeps its own tooltip table inline in `ui/wireframes/strategy.html` (37 keys). The Python UI and the Node UI must read the same source.

## Decision

1. **Format: JSON.** The file is `config/glossary.json`. Python reads it with the standard library. Node reads it with `JSON.parse`. No new dependency is needed on either side. YAML and TOML were rejected: they need a parser on the Node side.
2. **One entry per column key.** Each entry has these fields:

   | Field | Type | Rule |
   |---|---|---|
   | `key` | string | The column name used in the workbook, the packet and the UI. Renamed columns use the new name only (see Renames). |
   | `visibility` | `"excel"`, `"ui"`, `"prompt"`, `"backend"` (list) | Where the column is shown. A column may have several. |
   | `label` | string, optional | Short display label. Required only when the column is shown and the data exists. |
   | `tooltip` | string, optional | One or two plain-English sentences. Required only for shown columns with data. Hidden columns (`visibility` is `["backend"]` only) must not have one. |
   | `explanation` | string, optional | Full text shown under the tooltip. Same rule as `tooltip`. |
   | `derivation_kind` | `"formula"` or `"producer"` | `formula` means the entry states a formula that a test checks. `producer` means the entry names the step that writes the value. |
   | `formula` | string | Required when `derivation_kind` is `formula`. |
   | `producer` | string | Required when `derivation_kind` is `producer`. Module and function name. |
   | `provisional` | boolean | `true` for entries that depend on parked logic (`stance`, `stance_score`, `stance_why`, `breakout_quality`). |
   | `wording_status` | `"draft"` or `"approved"` | Set to `"approved"` only after the user signs off the wording. |

3. **Wording is generated by an LLM from the data.** A column with no data gets no entry. The generator is a separate step and is not part of the loader. Entries written by the generator start as `"draft"`. The user approves them, and the build check reports any `draft` entry for a shown column.
4. **Renames:** one commit per rename, with a grep test that fails if the old name still appears in the workbook, the packet or the UI. No alias layer.
5. **Stored runs** are re-read through a key mapping. The mapping lives in `config/glossary_renames.json` and is used only when reading old runs.
6. **Loader:** `scanner/glossary.py` exposes `load_glossary()` and `entry_for(key)`. It is the only code that reads `config/glossary.json`.
7. **Forbidden terms:** `config/glossary_forbidden.json` lists the banned adjectives (from the plain-English rules) and the Screener fundamentals source name. The check runs on every output: the workbook, the prompt text, model output and the UI files.

## Gates

| Check | Result on failure |
|---|---|
| A column in the workbook, packet or UI has no entry | Build prints a warning. Test suite fails. |
| A formula entry disagrees with the code's output (hand-computed fixture) | Test fails. |
| A forbidden term (Screener name or banned adjective) appears in any output or UI file | Test fails. |
| A shown column has a `draft` entry | Build prints a warning. |
| Tooltip present on a backend-only column | Test fails. |

The pytest gate is `testpaths = ["tests"]` in `pyproject.toml`. The new tests are `tests/test_glossary.py` (loader and coverage) and `tests/test_glossary_terms.py` (forbidden terms).

## Consequences

* Excel headers are display labels read from the file. Backend keys are not shown.
* The wireframe keeps its inline tooltips until the wireframe sign-off. Wiring the wireframe to `config/glossary.json` is a separate step after sign-off.
* Node UI work reads the same JSON file when its build starts.
* `above_sma200` and `above_ema50` stay in the backend. `portfolio.py` uses `above_sma200`.

## Sign-off decisions (2026-10-31)

* The five required fields (`key`, `visibility`, `derivation_kind`, `provisional`, `wording_status`) stay required. None becomes optional.
* The gate does not enforce these four rules. They stay in the review checklist: label required when a column is shown with data; a tooltip length limit; the `module.function` format for `producer`; `provisional` is true for the stance and breakout columns.
* The loader rejects an entry whose `key` field differs from the name it is stored under in `config/glossary.json`. Decided 2026-10-31.

## Not decided here

* The exact wording of any entry. That belongs to the LLM generator plus the user's approval.
* Whether `stance` labels change. That waits for the scoring redesign.
